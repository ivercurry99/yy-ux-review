# 10 个 UX 维度详解

每个维度包含：定义 → 判断标准 → 检查清单 → 典型反例 → 指标映射。

评分统一为 1-5 分（规则见 methodology.md）。打分时必须有证据支撑，证据不足标"存疑"并在报告中说明验证方式。

---

## 1. 有用（Useful）—— 解决真问题，而非堆砌功能

**定义**：产品是否服务于真实的用户目标，功能是否转化为对行动的支持。

**判断标准**：明确"谁在什么场景下，想完成什么任务"。信息只有转化为行动支持才算有用。

**检查清单**：
- [ ] 能否说清每个功能对应"谁 + 什么场景 + 什么任务"？
- [ ] 去掉该功能，用户能否仍完成核心任务？（能 → 该功能可疑）
- [ ] 展示的数据是否给出了下一步行动建议，还是只陈列数字？
- [ ] 核心任务的入口是否在产品主路径上，而非边角位置？

**典型反例**：天气 App 只展示温湿度，不提供穿衣/带伞建议——信息未转化为行动支持。

**指标映射**：核心功能使用率、功能留存率。

---

## 2. 可用（Usable）—— 新手能上手，老手不卡顿，中断可续上

**定义**：不同熟练度的用户都能顺畅操作，出错有明确恢复路径。

**检查清单**：
- [ ] 新用户不看教程能否理解界面并完成任务？
- [ ] 熟练用户的高频操作是否流畅，无多余打断？
- [ ] 用户隔一段时间回来，能否快速唤起使用记忆？
- [ ] 出错时是否告知"错在哪 + 怎么改"，而非只提示失败？
- [ ] 关键操作前是否有状态预览或格式示例？

**典型反例**：注册页只提示"输入错误"却不说明格式要求，用户盲目试错。

**指标映射**：新用户首次任务完成率、SUS 可用性评分、出错后恢复率。

---

## 3. 可找到（Findable）—— 入口符合用户心智模型

**定义**：信息架构与命名匹配用户的直觉，而不是匹配设计师的脑内导航。

**检查清单**：
- [ ] 让用户独立完成典型任务（如"申请发票"），其首步点击位置是否正确？
- [ ] 导航命名是否用了用户会用的词，而非内部术语？
- [ ] 功能分类是否符合用户心智？（"发票"该在"订单"里还是"增值服务"里？）
- [ ] 搜索/筛选能否覆盖"想不到分类"的用户？
- [ ] 层级是否过深？（超过 3 层要警惕）

**验证方法**：设计师熟悉 ≠ 用户直觉匹配。必须观察真实用户或模拟首用视角。

**指标映射**：任务寻路成功率、首步点击正确率、搜索使用率（过高说明导航失效）。

---

## 4. 可信赖（Trustworthy）—— 信任来自透明规则

**定义**：信任由三要素共建——准确的信息、清晰的规则、稳定的服务承诺。不止于精致界面。

**检查清单**：
- [ ] 价格/库存/状态信息是否实时准确？
- [ ] 结算前是否完整披露全部费用（运费、税费、附加费）？
- [ ] 权限申请是否说明用途？
- [ ] 优惠/活动的使用条件是否清晰可查？
- [ ] 是否有明确的问题反馈渠道与客服响应承诺？
- [ ] 隐私政策、数据用途是否用户可读（非法律八股）？

**典型反例**：结算最后一步才冒出运费；索取通讯录权限不说明用途。

**指标映射**：结算放弃率、权限拒绝率、客服首次响应时长。

---

## 5. 可达（Accessible）—— 无障碍是底线，不是加分项

**定义**：为不同能力（视觉/运动/认知障碍）与不同情境（强光、单手、静音）的用户兜底。

**硬性要求清单**：
- [ ] 普通文本对比度 ≥ 4.5:1，大字号文本 ≥ 3:1
- [ ] 表单错误用**文字 + 颜色**双重提示（不只靠红色）
- [ ] 所有交互控件支持键盘导航，焦点顺序合理
- [ ] 控件可被读屏软件识别（有语义标签/alt 文本）
- [ ] 文字放大到 200% 后内容不被遮挡、功能仍可操作
- [ ] 触屏热区 ≥ 44×44pt
- [ ] 信息不只依赖颜色/声音单一通道传达

**指标映射**：WCAG 合规等级、键盘任务完成率。

---

## 6. 令人愉悦（Pleasurable）—— 情绪体验适配产品基因

**定义**：情绪设计服务于产品气质。财务工具追求清晰稳定带来的安心感；儿童教育产品用插画与反馈激发兴趣。**拒绝为动效而动效**。

**检查清单**：
- [ ] 情绪设计是否与产品基因匹配？（对账软件做炫技动效 = 减分）
- [ ] 动效是否干扰或拖延主任务？
- [ ] 提示语、空态文案是否自然有人味，还是机器人腔？
- [ ] 是否有"设计偏好绑架用户感受"的情况（设计师觉得酷，用户觉得吵）？
- [ ] 成功/完成时刻是否有恰当的正反馈？

**指标映射**：NPS、主观满意度、动效关闭率。

---

## 7. 有价值（Valuable）—— 让用户"看见"价值

**定义**：价值感知需要设计。用户拥有功能 ≠ 用户感知到价值。

**检查清单**：
- [ ] 用户能否清晰说出"它帮我解决了什么"？
- [ ] 后台默默做的事（自动备份、智能同步）是否有可见的价值证据（最近备份时间、一键恢复入口）？
- [ ] 价值是否在关键时机被呈现（首次完成、周期回顾）？
- [ ] 组织是否有持续投入维持服务的能力与信号？（长期不更新 = 价值衰减信号）

**典型反例**：自动备份功能不展示最近备份时间、无恢复入口，用户无法判断其可靠性。

**指标映射**：留存率、付费转化率、"价值感知"访谈提及率。

---

## 8. 一致（Consistent）—— 跨页面、跨平台、跨时间的体验契约

**三重统一**：
- **视觉一致**：同一操作按钮样式统一
- **交互一致**：同类操作行为一致（收藏/关注不混用）
- **语言一致**：术语不随意替换

**检查清单**：
- [ ] 同一功能在不同页面的入口、图标、命名是否一致？
- [ ] 是否有设计系统/组件库支撑落地？
- [ ] 跨平台（iOS/Android/Web）核心逻辑是否一致，同时尊重平台原生习惯（手势、导航范式）？
- [ ] 改版后旧用户的肌肉记忆是否被无故打破？

**指标映射**：跨端任务完成率差值、界面走查不一致项数量。

---

## 9. 高效（Efficient）—— 降低总耗时与认知负担

**定义**：高效 = 总耗时 + 认知负担双降，**不是单纯减少点击次数**。

**检查清单**：
- [ ] 高频操作是否有批量处理、快捷键、智能默认值？
- [ ] 是否保留最近使用记录/历史，避免重复输入？
- [ ] 表单是否只问必要信息，能推断的不问？
- [ ] 是否存在"虚假高效"：为省一次点击把 20 个选项塞进一屏，加剧选择疲劳与误操作？
- [ ] 等待时间是否有进度反馈或被异步化？

**指标映射**：核心任务平均耗时、操作步数、误操作率。

---

## 10. 容错与韧性（Forgiving & Resilient）—— 允许犯错，帮用户优雅翻盘

**三段式防护**：
- **预防**：不可逆操作前二次确认 + 后果说明
- **反馈**：操作失败时保留用户已投入的内容（已填表单不清空），告知重试方式
- **恢复**：提供撤销、草稿保存、状态回溯

**检查清单**：
- [ ] 删除/支付等不可逆操作是否有确认与后果说明？
- [ ] 提交失败后已填内容是否保留？
- [ ] 是否有撤销（Undo）机制，而非只有"确认对话框"？
- [ ] 长流程是否有草稿自动保存？
- [ ] 防护强度是否按**后果严重性 × 恢复成本**分级？（不是所有操作都要弹窗——过度防护本身损害效率）

**指标映射**：错误率、出错后放弃率、数据丢失投诉量。

---

## 维度间关系速记

- **有用 + 有价值** = 值的做（解决真问题且被感知）
- **可用 + 高效 + 容错** = 顺手做（不同熟练度都顺畅，犯错有救）
- **可找到 + 一致** = 找得到（心智匹配，处处如预期）
- **可信赖 + 可达** = 放心用（透明规则，人人可用）
- **令人愉悦** = 愿意再来（适配基因的调味剂，过量有毒）

**权衡原则**：维度冲突时（如效率 vs 新手友好），回到锁定的目标用户与任务场景裁决，不存在脱离场景的"绝对正确"。
